Unix-like operační systémy

Jak funguje systém, ve kterém většina práce probíhá přes procesy, služby, uživatele, oprávnění a soubory, a proč je Linux tak důležitý pro servery, cloud i vývoj.

Základní pojmy

Kernel

Jádro OS. Zprostředkuje přístup k CPU, paměti, zařízením a procesům.

Process

Běžící program. Má vlastní adresní prostor, PID a oprávnění.

Daemon

Proces běžící na pozadí, typicky poskytující službu. Často končí na d: sshd, systemd.

Shell

Program, který interpretuje příkazy uživatele. Např. Bash, Zsh.

Vrstvy systému

SHELL & NÁSTROJEbash · ls · grep · ssh · systemctl
SYSTÉMOVÉ KNIHOVNY / SLUŽBYlibc · systemd · síťové služby

HARDWARECPU · RAM · disk · síťová karta · zařízení

Stručná historie

1969
Vzniká Unix v Bellových laboratořích AT&T.
1970–80s
Unix se šíří mezi univerzitami a vznikají jeho varianty.
1983
Richard Stallman zahajuje projekt GNU.
1991
Linus Torvalds zveřejňuje Linux kernel.

Unix-like neznamená „Unix“. Jde o systémy inspirované Unixem nebo implementující podobné principy a rozhraní.

Linux není jeden OS. Distribuce spojuje kernel, systémové nástroje, správu balíčků, konfiguraci a aplikace.

Proč shell?

Příkazy lze řetězit, přesměrovat a automatizovat.

$ ps aux | grep ssh
$ cat log.txt | grep ERROR > chyby.txt
$ chmod +x script.sh
$ ./script.sh
Tip: | předá výstup dalšímu příkazu. > zapíše výstup do souboru. Víc v kapitole 6.

Uživatelé, skupiny a superuser

Každý proces běží pod určitým uživatelem. Uživatel může být členem více skupin. Oprávnění se posuzují jako owner / group / others.

root superuser má velmi rozsáhlá oprávnění: může měnit systém, instalovat software, spravovat uživatele i přistupovat k souborům bez běžných omezení.

sudo umožní oprávněnému uživateli spustit konkrétní příkaz s vyššími právy — bezpečnější než běžně pracovat jako root.

Oprávnění v praxi

$ ls -l script.sh
-rwxr-x--- 1 alice dev 120 script.sh
 ↑↑↑ ↑↑↑ ↑↑↑
 owner group others

r = read     4
w = write    2
x = execute  1

rwxr-x--- = vlastník čte/zapisuje/spouští, skupina čte/spouští, ostatní nemají práva.

Souborový systém

V Unix-like systémech je vše organizováno do jediného stromu začínajícího kořenem /. Připojené disky a zařízení se objevují v tomto stromu.

CestaVýznam
/kořen celého souborového systému
/homedomovské adresáře uživatelů
/etckonfigurace systému a služeb
/varproměnlivá data, logy, cache
/usrprogramy, knihovny a sdílená data
/tmpdočasná data
/devsouborové rozhraní k zařízením

Zapamatuj si

  • Kernel řídí zdroje a hardware.
  • Daemon běží na pozadí jako služba.
  • Shell interpretuje příkazy.
  • Root má privilegovaná oprávnění.
  • chmod mění oprávnění.
  • / je kořen stromu souborového systému.
  • Distribuce není totéž co Linux kernel.

„Všechno je soubor“

V Unix-like systémech se se souborovým rozhraním pracuje nejen s běžnými soubory, ale také s adresáři a mnoha zařízeními či speciálními objekty.

ZnakTypPříklad
-běžný soubornotes.txt, program.py
dadresář/home/alice
lsymbolický odkazlatest -> release
cznakové zařízení/dev/tty
bblokové zařízení/dev/sda
ppojmenovaná rouraFIFO
ssocketkomunikace procesů

Nejde o to, že každý objekt je doslova běžný soubor. Unixový princip je, že mnoho různých zdrojů lze ovládat podobným souborovým rozhraním.

Jak typ poznám?

$ ls -l
-rw-r--r--  notes.txt
drwxr-xr-x  Dokumenty
lrwxrwxrwx  latest -> release
crw-rw----  /dev/tty

$ file notes.txt
notes.txt: UTF-8 Unicode text

$ stat notes.txt
První znak výstupu ls -l určuje typ objektu. file se pokouší určit obsah běžného souboru.

Linux lze vyzkoušet bez zásahu do počítače, provozovat vedle Windows, ve virtuálním stroji, nebo nasadit na server v cloudu. Způsob volíme podle účelu.

Příprava instalačního média

  1. Stáhnout obraz z debian.org: netinst (malý, balíčky stahuje ze sítě) nebo DVD.
  2. Ověřit kontrolní součet, že soubor není poškozený ani podvržený.
  3. Zapsat obraz na USB: Rufus nebo balenaEtcher (Windows), dd (Linux).
  4. V UEFI/BIOS nastavit start z USB (často F12, F2 nebo Esc).
$ sha256sum debian-13.1.0-amd64-netinst.iso
a1b2c3…  debian-13.1.0-amd64-netinst.iso
# porovnat se souborem SHA256SUMS na webu

$ sudo dd if=debian-13.1.0-amd64-netinst.iso of=/dev/sdX bs=4M status=progress oflag=sync
# /dev/sdX = celý flash disk (ověřit přes lsblk!)

Průběh instalace Debianu

  1. Jazyk, oblast a rozložení klávesnice.
  2. Síť: název počítače (hostname) a doména.
  3. Heslo roota. Když ho necháte prázdné, root se zamkne a první uživatel dostane sudo.
  4. Běžný uživatel: celé jméno, login, heslo.
  5. Rozdělení disku: řízené (celý disk), s LVM, šifrované LVM, nebo ručně.
  6. Zrcadlo archivu balíčků (deb.debian.org).
  7. Výběr softwaru (tasksel): prostředí GUI, SSH server, standardní nástroje.
  8. Instalace zavaděče GRUB a restart.

bash a souborový systém

Bash je výchozí shell v Debianu. Každý příkaz má stejnou stavbu, a jakmile ji umíme číst, umíme číst i nápovědu ke kterémukoli jinému příkazu.

Syntaxe příkazu

příkaz [-přepínače] [argumenty]
$ ls -l -a /etc          # krátké přepínače zvlášť
$ ls -la /etc            # … nebo spojené
$ ls --all --human-readable -l
$ cp -r zdroj/ cil/      # argumenty: odkud, kam

Výzva (prompt)

alice@lab-pc01:~/projekt$       # uživatel@počítač:adresář  $ = běžný uživatel
root@lab-pc01:/etc#             # # = root (opatrně!)

Navigace a prohlížení

Vytváření, kopírování, přesun, mazání

$ mkdir projekt              # nový adresář
$ mkdir -p a/b/c             # včetně rodičů
$ touch poznamky.txt         # prázdný soubor / aktualizace času

$ cp a.txt b.txt             # kopie souboru
$ cp -r projekt/ zaloha/     # kopie adresáře (rekurzivně)
$ cp -i a.txt b.txt          # zeptá se před přepsáním

$ mv a.txt docs/             # přesun
$ mv stary.txt novy.txt      # přejmenování

$ rm b.txt                   # smazat soubor
$ rmdir prazdny/             # smazat prázdný adresář
$ rm -r zaloha/              # smazat adresář s obsahem
$ rm -ri zaloha/             # … s potvrzováním
Pozor: rm nemá koš. Co smažeme, je pryč. Před rm -r s hvězdičkou si nejdřív pusťte ls se stejným vzorem.

Přesměrování a roury

Unixová filozofie: každý program dělá jednu věc dobře a umí spolupracovat s ostatními. Spojením malých nástrojů rourou vzniká nástroj nový.

Tři standardní proudy

ČísloNázevVýchozí
0stdin — vstupklávesnice
1stdout — výstupterminál
2stderr — chybyterminál
stdin 0→příkaz→stdout 1
stdin 0→příkaz↘stderr 2

Výstup a chyby jdou na obrazovku zvlášť, a proto je lze přesměrovat každý jinam.

Přesměrování

ZápisVýznam
prikaz > souborstdout do souboru (přepíše)
prikaz >> souborstdout na konec souboru (připojí)
prikaz < souborstdin ze souboru
prikaz 2> chyby.logjen chyby do souboru
prikaz > vse.log 2>&1výstup i chyby do jednoho souboru
prikaz &> vse.logtotéž, kratší zápis v bashi
prikaz 2> /dev/nullchyby zahodit
$ ls /etc > seznam.txt
$ date >> zaznam.log
$ find / -name "*.conf" 2>/dev/null     # bez hlášek „Permission denied“
$ sort < jmena.txt

Roura |

prikaz1 | prikaz2 | prikaz3

stdout levého příkazu se stane stdin pravého. Data tečou zleva doprava a nic se neukládá na disk.

$ ls -l /etc | less                    # listování dlouhým výpisem
$ cat /etc/passwd | wc -l              # kolik je účtů
$ ps aux | grep sshd                   # najít proces
$ cut -d: -f1 /etc/passwd | sort       # seřazená jména účtů
$ du -ah ~ | sort -rh | head -5        # 5 největších položek
$ history | awk '{print $2}' | sort | uniq -c | sort -rn | head
                                       # moje nejčastější příkazy

Regulární výrazy

Regulární výraz popisuje vzor textu: „řádek začínající číslem“, „cokoliv, co vypadá jako e-mail“. S rourami z minulé kapitoly z nich vzniká rychlý nástroj na vytahování dat.

Základní metaznaky

ZnakVýznamPříklad → shoda
.jeden libovolný znakk.t → kat, kot, k9t
^ / $začátek / konec řádku^# → komentář
*0× a víc předchozíab*c → ac, abbc
+1× a víc[0-9]+ → 7, 2026
?0× nebo 1×https? → http, https
{n,m}n až m opakování[0-9]{3} → 420
[abc]jeden ze znaků[Ll]inux
[^0-9]jakýkoli znak kroměne-číslice
( | )skupina, alternativa(jpg|png)$
\.doslovná tečka\.conf$

+ ? { } ( ) | fungují bez lomítek jen v rozšířené syntaxi: grep -E, sed -E.

grep — hledání řádků

grep [-E -i -v -o -n -c -r] 'vzor' [soubory]
$ grep root /etc/passwd                # řádky obsahující root
$ grep -i error app.log                # bez ohledu na velikost písmen
$ grep -v '^#' /etc/ssh/sshd_config    # bez komentářů
$ grep -vE '^(#|$)' sshd_config        # bez komentářů a prázdných řádků
$ grep -n 'Port' sshd_config           # s čísly řádků
$ grep -c 'bash$' /etc/passwd          # kolik účtů má bash
$ grep -r 'listen' /etc/nginx/         # rekurzivně v adresáři
$ grep -oE '[0-9]+' text.txt           # vypsat jen shody (-o)

Třídy znaků POSIX

[[:digit:]] číslice · [[:alpha:]] písmena · [[:space:]] mezery · [[:upper:]] velká písmena

sed — nahrazování

sed -E 's/vzor/náhrada/g' soubor
$ sed 's/http:/https:/g' odkazy.txt            # výpis s náhradou
$ sed -i 's/^#Port 22/Port 2222/' sshd_config  # -i = přímo v souboru
$ sed -i.bak 's/old/new/g' konfig.txt          # se zálohou .bak
$ sed -n '10,20p' soubor.txt                   # jen řádky 10–20
$ sed '/^$/d' soubor.txt                       # smazat prázdné řádky

# skupiny ( ) a odkazy \1 \2: přehodit datum 2026-10-01 → 01.10.2026
$ echo "2026-10-01" | sed -E 's/([0-9]{4})-([0-9]{2})-([0-9]{2})/\3.\2.\1/'

Data z načtené webové stránky

curl stáhne stránku na stdout, regulární výrazy z ní vyberou to, co potřebujeme.

# kurz EUR z denního kurzovního lístku ČNB (formát země|měna|množství|kód|kurz)
$ curl -s https://www.cnb.cz/cs/financni-trhy/devizovy-trh/kurzy-devizoveho-trhu/kurzy-devizoveho-trhu/denni_kurz.txt \
    | grep '|EUR|' | cut -d'|' -f5

# titulek stránky
$ curl -s https://www.debian.org | grep -oE '<title>[^<]*' | sed 's/<title>//'

# všechny odkazy na stránce, bez duplicit
$ curl -s https://www.debian.org \
    | grep -oE 'href="https?://[^"]+"' \
    | sed -E 's/href="(.*)"/\1/' | sort -u

# všechny e-mailové adresy na stránce
$ curl -s https://example.org/kontakty \
    | grep -oE '[[:alnum:]._%+-]+@[[:alnum:].-]+\.[a-z]{2,}' | sort -u
Regex na HTML stačí na jednoduché úlohy. Na složitější stránky je spolehlivější parser (např. Python s BeautifulSoup) nebo API, pokud ho web nabízí.

Procesy a služby

Každý spuštěný program je proces s vlastním číslem PID. Umíme je vypsat, sledovat, poslat na pozadí a ukončit, a dlouhodobě běžící služby spravujeme přes systemd.

Výpis procesů

$ ps                      # procesy v tomto terminálu
$ ps aux                  # všechny procesy všech uživatelů
$ ps aux --sort=-%mem | head    # největší spotřeba paměti
$ ps -ef --forest         # i s rodiči (PPID)
$ pstree -p               # strom procesů
$ pgrep -a nginx          # PID podle jména
$ pidof sshd

$ ps aux | head -3
USER   PID %CPU %MEM    VSZ   RSS TTY  STAT START  TIME COMMAND
root     1  0.0  0.3 168M  12M ?    Ss   08:01  0:02 /sbin/init
alice 2412  1.2  2.1 812M  84M pts/0 Sl  08:15  0:30 python3 app.py

Stavy procesu (STAT)

Rběží nebo čeká na CPU
Sspí, čeká na událost (nejčastější)
Dnepřerušitelné čekání, typicky na disk
Tzastavený (Ctrl+Z)
Zzombie: skončil, rodič si nevyzvedl výsledek

Sledování v reálném čase

top je vždy k dispozici, htop (apt install htop) je přehlednější a ovládá se šipkami. V top: M řadit podle paměti, P podle CPU, k ukončit proces, q konec.

  … Ctrl+Z …                    pozastavit
$ bg %1                       # pokračovat na pozadí

$ nohup ./zaloha.sh > zaloha.log 2>&1 &
                              # přežije i odhlášení
$ disown %1                   # odpojit úlohu od shellu

Příkazy správce: sudo a su

Na správu systému potřebujeme práva roota. Pracovat jako root celý den je ale nebezpečné, proto si práva půjčujeme jen na konkrétní příkaz.

sudo — jeden příkaz jako root

sudo [-u uživatel] příkaz
$ sudo apt update                   # zadává se VLASTNÍ heslo
$ sudo -u www-data ls /var/www      # jako jiný uživatel
$ sudo -l                           # co smím přes sudo spouštět
$ sudo -i                           # přihlašovací shell roota
$ sudo !!                           # zopakovat poslední příkaz se sudo
$ sudoedit /etc/hosts               # bezpečná úprava souboru
$ sudo -k                           # zapomenout heslo hned

Po zadání si sudo heslo pamatuje 15 minut. Každé použití se zapisuje do logu.

su — přepnutí uživatele

su [-] [uživatel]
$ su -                    # stát se rootem, zadává se heslo ROOTA
$ su - alice              # stát se uživatelem alice
$ su alice                # bez „-“: zůstane prostředí a adresář
$ su -c 'apt update' -    # jeden příkaz jako root
$ exit                    # návrat

$ whoami
$ id
su - (s pomlčkou) načte prostředí cílového uživatele včetně PATH. Bez pomlčky mohou chybět příkazy z /usr/sbin.

sudo × su

sudosu
Čí heslovlastní heslo uživateleheslo cílového účtu (roota)
Rozsahjeden příkaz, lze omezit na konkrétní příkazycelý shell, plná práva
Záznamkaždý příkaz v logu s jménem uživatelejen že se někdo přepnul
Sdílení hesla rootanení potřeba, root může být zamčenýkaždý správce zná heslo roota
Kdyběžná správa (doporučeno)záchrana, systémy bez sudo, delší práce jako jiný uživatel

Kdo smí sudo

V Debianu dostanou plná práva členové skupiny sudo (v rodině Red Hat je to skupina wheel).

$ su -                           # pokud sudo zatím nemáme
# apt install sudo               # když bylo při instalaci zadáno heslo roota
# usermod -aG sudo alice
# exit
# alice se musí odhlásit a znovu přihlásit

$ groups alice
alice : alice sudo

# kdo sudo použil
$ sudo journalctl _COMM=sudo --since today

Soubor sudoers

Pravidla jsou v /etc/sudoers a v souborech v /etc/sudoers.d/. Upravují se jen přes visudo, které před uložením zkontroluje syntaxi.

$ sudo visudo
$ sudo visudo -f /etc/sudoers.d/web

# kdo   odkud=(jako koho)  co
root    ALL=(ALL:ALL) ALL
%sudo   ALL=(ALL:ALL) ALL            # % = skupina

# bob smí jen restartovat web
bob     ALL=(root) /usr/bin/systemctl restart nginx
Chyba v sudoers může zablokovat sudo všem. Proto vždy visudo, nikdy přímo editor. Volbu NOPASSWD používejte jen u úzce omezených příkazů.

Skupiny a smazání účtu

$ sudo addgroup ucitele               # nebo groupadd

Přidělování a odebírání oprávnění

Navazujeme na kapitolu 1: každý soubor má vlastníka, skupinu a tři trojice práv. Teď je budeme měnit, a to i jemněji, než dovoluje klasické rwx.

Co znamená r, w, x

u souboruu adresáře
rčíst obsahvypsat seznam souborů
wměnit obsahvytvářet, mazat, přejmenovat soubory uvnitř
xspustitvstoupit (cd) a přistupovat k souborům

Smazání souboru tedy řídí právo w na adresáři, ne na souboru samotném.

chmod — symbolický zápis

chmod [ugoa][+-=][rwx] soubor

u vlastník · g skupina · o ostatní · a všichni  |  + přidat · - odebrat · = nastavit přesně

$ chmod u+x skript.sh             # vlastník smí spouštět
$ chmod g+w sdilene.txt           # skupina smí zapisovat
$ chmod o-rwx tajne.txt           # ostatním odebrat vše
$ chmod go-w report.pdf           # skupině i ostatním odebrat zápis
$ chmod a+r verejne.html          # všichni smí číst
$ chmod u=rw,g=r,o= data.csv      # přesně rw-r-----
$ chmod -R g+rX projekt/          # rekurzivně; X = x jen adresářům

chmod — číselný (oktalový) zápis

Sečteme hodnoty r = 4, w = 2, x = 1 pro každou trojici zvlášť.

ČísloPrávaTypické použití
755rwxr-xr-xskripty, programy, adresáře
644rw-r--r--běžné soubory, webové stránky
700rwx------soukromý adresář, ~/.ssh
600rw-------soukromý klíč, soubor s heslem
750rwxr-x---adresář týmu, ostatní nemají přístup
660rw-rw----sdílený soubor ve skupině
$ chmod 600 ~/.ssh/id_ed25519
$ chmod 755 zaloha.sh
$ stat -c '%a %A %n' zaloha.sh

$ sudo chown jan soubor.txt            # nový vlastník
$ sudo chown jan:ucitele soubor.txt    # vlastník i skupina
$ sudo chown :ucitele soubor.txt       # jen skupina
$ sudo chgrp ucitele soubor.txt        # totéž
$ sudo chown -R www-data:www-data /var/www/web

Vlastníka může měnit jen root. Běžný uživatel může změnit skupinu svého souboru na jinou svou skupinu.

umask — výchozí práva

$ umask
0022       # nové soubory 644, adresáře 755
$ umask 027   # → 640 a 750

Práva přes členství ve skupině

Nejčistší způsob, jak dát přístup více lidem: přidělit práva skupině a lidi do ní přidávat a odebírat.

# sdílený adresář pro tým
$ sudo addgroup projekt
$ sudo mkdir /srv/projekt
$ sudo chown root:projekt /srv/projekt
$ sudo chmod 2770 /srv/projekt     # 2 = SGID, nové soubory dědí skupinu

# přidělit přístup
$ sudo gpasswd -a jan projekt
# odebrat přístup
$ sudo gpasswd -d jan projekt

ACL — práva pro konkrétního uživatele

Klasická práva znají jen jednoho vlastníka a jednu skupinu. Když potřebujeme dát přístup jednomu dalšímu člověku bez nové skupiny, použijeme ACL (sudo apt install acl).

# přidělit
$ setfacl -m u:petr:rw zadani.odt          # petr smí číst a zapisovat
$ setfacl -m g:ucitele:r hodnoceni.ods     # skupina smí číst
$ setfacl -R -m u:petr:rwX projekt/        # rekurzivně
$ setfacl -d -m u:petr:rw projekt/         # výchozí pro nové soubory
# zkontrolovat a odebrat
$ getfacl zadani.odt
user::rw-
user:petr:rw-
group::r--
mask::rw-
other::---
$ setfacl -x u:petr zadani.odt             # odebrat petrovi
$ setfacl -b zadani.odt                    # odebrat všechna ACL
Soubor s ACL poznáte podle znaménka + ve výpisu: -rw-rw----+.

Instalace a aktualizace balíčků

Software v Debianu instalujeme z repozitářů pomocí apt. Ten stáhne balíček, ověří jeho podpis, doinstaluje závislosti a později ho umí i aktualizovat.

apt — každodenní příkazy

sudo apt update|upgrade|install|remove|purge|search|show [balíček]
$ sudo apt update                # stáhnout aktuální seznam balíčků
$ apt list --upgradable          # co se dá aktualizovat
$ sudo apt upgrade               # aktualizovat nainstalované
$ sudo apt full-upgrade          # … i když je třeba něco přidat/odebrat

$ apt search "web server"        # hledat
$ apt show nginx                 # popis, verze, závislosti
$ sudo apt install nginx curl    # nainstalovat (i víc najednou)
$ sudo apt install -y htop       # bez dotazu na potvrzení

$ sudo apt remove nginx          # odebrat, konfigurace zůstane
$ sudo apt purge nginx           # odebrat včetně konfigurace
$ sudo apt autoremove            # uklidit nepotřebné závislosti
$ sudo apt clean                 # smazat stažené .deb z cache

Jak apt funguje

repozitář→apt update→seznam balíčků
apt install→stáhne .deb→ověří podpis→dpkg
update ≠ upgrade. update jen zjistí, co je nového. Nainstaluje to až upgrade. Proto se píšou spolu: sudo apt update && sudo apt upgrade.

apt × apt-get

apt je pohodlnější pro člověka (průběh, barvy). Ve skriptech se používá apt-get, protože jeho výstup se nemění.

dpkg — práce s jednotlivými .deb

$ sudo apt install ./program_1.2_amd64.deb   # doporučeno: vyřeší závislosti
$ sudo dpkg -i program_1.2_amd64.deb         # nízkoúrovňově
$ sudo apt -f install                        # dořešit chybějící závislosti

$ dpkg -l | grep nginx           # je nainstalován?
$ dpkg -L nginx                  # jaké soubory balíček obsahuje
$ dpkg -S /usr/sbin/sshd         # ke kterému balíčku soubor patří
$ apt list --installed | wc -l   # počet nainstalovaných
.deb soubory stažené z neznámých webů nejsou ověřené. Instalujte primárně z oficiálních repozitářů.
