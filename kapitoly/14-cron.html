Plánování úloh: cron

Záloha každou noc, úklid jednou týdně, kontrola disku každých pět minut. Cron je služba, která spouští příkazy a skripty v zadaný čas, i když u počítače nikdo nesedí. V kapitole si ukážeme, jak úlohu vytvořit, spravovat a zase odstranit.

Jak cron funguje

Démon cron běží na pozadí a každou minutu projde tabulky úloh, kterým se říká crontab. Když čas úlohy odpovídá aktuální minutě, spustí ji pod daným uživatelem.

Vytvoření

crontab -e a první úloha

Vytvoření úlohy: crontab -e

  1. Spusťte crontab -e. Napoprvé se Debian zeptá, jaký editor chcete používat; nejjednodušší je nano. Volbu změníte později příkazem select-editor.
  2. Na konec souboru napište řádek s úlohou. Řádky s # jsou komentáře.
  3. Uložte a zavřete editor. Crontab se při uložení zkontroluje a zapne, cron ho není třeba restartovat.
$ crontab -l
no crontab for petr
$ crontab -e
no crontab for petr - using an empty one
crontab: installing new crontab
$ crontab -l
# m h  dom mon dow   command
*/5 * * * * date >> /home/petr/cas.log

Po pár minutách přibydou v ~/cas.log řádky s časem. To je nejrychlejší test, že cron funguje.

Chyba v zápisu

Crontab s chybou se neuloží. Editor se zeptá, zda ho chcete otevřít znovu a opravit.

$ crontab -e
"/tmp/crontab.Xb3kQ/crontab":24: bad minute
errors in crontab file, can't install.
Do you want to retry the same edit? (y/n)

Na co si dát pozor

  • Poslední řádek musí končit Enterem, jinak se úloha nenačte.
  • Znak % má v crontabu zvláštní význam (nový řádek). V příkazu ho pište jako \%: date +\%F.
  • Crontab needitujte přímo ve /var/spool/cron/, vždy přes crontab -e.

Prostředí, ve kterém úloha běží

Cron nespouští váš terminál. Nenačte ~/.bashrc, PATH obsahuje jen /usr/bin:/bin a výchozí shell je /bin/sh. Úloha, která v terminálu funguje, proto v cronu často selže.

# proměnné platí pro všechny úlohy pod nimi
SHELL=/bin/bash
PATH=/usr/local/bin:/usr/bin:/bin:/home/petr/bin
MAILTO=""

# vždy plné cesty ke skriptům i souborům
0 3 * * * /home/petr/bin/zaloha.sh /home/petr/projekt

Kam jde výstup

Co úloha vypíše, pošle cron e-mailem vlastníkovi (proměnná MAILTO). Na většině počítačů ale poštovní server není nainstalovaný a výstup se tiše zahodí. Lepší je výstup i chyby přesměrovat do logu (kapitola 6).

*/5 * * * * /home/petr/bin/kontrola.sh >> /home/petr/kontrola.log 2>&1
0 4 * * *   /home/petr/bin/uklid.sh > /dev/null 2>&1   # výstup zahodit

Bez přesměrování najdete v záznamech hlášku No MTA installed, discarding output.

Záloha a úpravy bez editoru

Crontab je obyčejný text, takže s ním fungují roury. Hodí se to ve skriptech nebo při zakládání úloh na více počítačích.

$ crontab -l > cron-zaloha.txt        # záloha
$ crontab cron-zaloha.txt             # obnova

# přidat úlohu na konec
$ (crontab -l 2>/dev/null; echo "0 7 * * 1-5 /home/petr/bin/ranni.sh") | crontab -

crontab - čte nový obsah ze stdin. 2>/dev/null skryje hlášku no crontab, pokud žádné úlohy ještě nejsou.

Systémové úlohy

/etc/crontab a soubory v /etc/cron.d/ mají mezi časem a příkazem navíc pole s uživatelem. Upravují se přímo editorem (jako root) a cron je načte sám.

SHELL=/bin/sh
# m h dom mon dow user  command
17 *  * * *   root  cd / && run-parts --report /etc/cron.hourly
25 6  * * *   root  test -x /usr/sbin/anacron || { cd / && run-parts --report /etc/cron.daily; }
47 6  * * 7   root  test -x /usr/sbin/anacron || { cd / && run-parts --report /etc/cron.weekly; }
52 6  1 * *   root  test -x /usr/sbin/anacron || { cd / && run-parts --report /etc/cron.monthly; }
$ sudo nano /etc/cron.d/zaloha-webu
30 1 * * *  www-data  /usr/local/bin/zaloha-webu.sh >> /var/log/zaloha-webu.log 2>&1

Pokud je nainstalovaný anacron (běžné na desktopu), postará se o denní, týdenní a měsíční úlohy i na počítači, který v danou chvíli nebyl zapnutý.

Adresáře cron.daily a spol.

Nejjednodušší cesta pro správce: spustitelný skript stačí nakopírovat do adresáře, čas neřešíte.

/etc/cron.hourly/každou hodinu
/etc/cron.daily/jednou denně
/etc/cron.weekly/jednou týdně
/etc/cron.monthly/jednou měsíčně
$ sudo cp uklid.sh /etc/cron.daily/uklid      # bez přípony!
$ sudo chmod +x /etc/cron.daily/uklid
$ run-parts --test /etc/cron.daily            # co se spustí
run-parts přeskočí soubory, jejichž název obsahuje tečku. Skript uklid.sh by se proto nikdy nespustil.

Kontrola, zda úloha proběhla

Debian 13 zapisuje záznamy do systemd journalu. Každé spuštění úlohy je v něm vidět jako řádek CMD.

$ journalctl -u cron --since today
lis 03 10:05:01 debian CRON[2841]: (petr) CMD (date >> /home/petr/cas.log)
lis 03 10:10:01 debian CRON[2907]: (petr) CMD (date >> /home/petr/cas.log)
$ journalctl -u cron -f                # sledovat živě
$ grep CRON /var/log/syslog            # na systémech s rsyslogem

Ani řádek CMD neznamená, že úloha uspěla. Výsledek ukáže až váš log z přesměrování.

Odstranění

jedna úloha, celý crontab, systémové úlohy

Odstranění jedné úlohy

Nejbezpečnější je otevřít crontab a řádek smazat nebo ho jen zakomentovat znakem #. Zakomentovanou úlohu později snadno znovu zapnete.

# */5 * * * * date >> /home/petr/cas.log      ← vypnuto
0 3 * * * /home/petr/bin/zaloha.sh /home/petr/projekt

Bez editoru, například ve skriptu, vyfiltrujte řádek grep -v a výsledek nahrajte zpět:

$ crontab -l | grep -v 'cas.log' | crontab -
$ crontab -l

Odstranění celého crontabu

$ crontab -l > cron-zaloha.txt       # nejdřív záloha
$ crontab -i -r
crontab: really delete petr's crontab? (y/n) y
$ crontab -l
no crontab for petr
$ sudo crontab -u jan -r       # crontab uživatele jan
Pozor: -r leží na klávesnici hned vedle -e. Překlep crontab -r smaže všechny úlohy bez ptaní. Proto se hodí záloha a alias alias crontab='crontab -i' v ~/.bashrc.

Systémové úlohy

Smaže se soubor: sudo rm /etc/cron.d/zaloha-webu nebo sudo rm /etc/cron.daily/uklid. Řádek v /etc/crontab odstraníte editorem.

Celý postup v praxi

skript → naplánování → kontrola → odstranění

Úklid dočasných souborů každou noc

#!/bin/bash
# Smaže z ~/docasne soubory starší než 7 dní a zapíše, co udělal
adr="$HOME/docasne"
smazano=$(find "$adr" -type f -mtime +7 -print -delete | wc -l)
echo "$(date '+%F %T') smazáno souborů: $smazano"
# 1) skript vyzkoušet ručně
$ chmod +x ~/bin/uklid.sh
$ ~/bin/uklid.sh
2026-11-03 10:12:40 smazáno souborů: 2

# 2) naplánovat na 3:15 každou noc
$ crontab -e                # v editoru přidat řádek:
  15 3 * * * /home/petr/bin/uklid.sh >> /home/petr/uklid.log 2>&1
crontab: installing new crontab

# 3) druhý den ráno zkontrolovat
$ cat ~/uklid.log
2026-11-04 03:15:01 smazáno souborů: 5

# 4) úlohu už nepotřebuji
$ crontab -l | grep -v 'uklid.sh' | crontab -

Datum v date '+%F %T' je uvnitř skriptu, ne přímo v crontabu, takže znak % není potřeba escapovat. Složitější příkazy proto patří do skriptu a v crontabu je jen jeho volání.

Zapamatuj si

  • Pořadí polí: minuta, hodina, den, měsíc, den v týdnu.
  • Úlohy upravujte přes crontab -e, vypisujte crontab -l.
  • V cronu vždy používejte plné cesty a výstup přesměrujte do logu.
  • Než úlohu naplánujete, vyzkoušejte skript ručně.
  • Před crontab -r si udělejte zálohu přes crontab -l > soubor.
